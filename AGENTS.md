# Repository Rules

## Git Workflow

- `main` is the protected branch. Do not commit directly to `main`.
- All work must start from a short-lived branch created from `main`.
- Changes must be merged back into `main` only through a pull request (PR) after review.
- Keep branches focused on a single task or feature.
- Before opening a PR, make sure the branch is up to date with `main` and that local checks pass when available.

## Branch Naming

- Use descriptive names such as `feature/add-users-route`, `fix/health-endpoint`, or `chore/setup-eslint`.
